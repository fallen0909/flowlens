# FlowLens 架构与维护

## 从哪里修改

| 目录 / 文件 | 职责 | 修改约束 |
| --- | --- | --- |
| `src/core/flowlens-core.js` | 采集、分组导航、渲染、媒体生命周期、大图及视频手势 | 共享状态与取消信号由核心拥有，异步结果提交前校验当前组 |
| `src/core/global-settings.js` | 两端设置同步 | 保持已有设置键兼容 |
| `src/core/optimizer.js` | 现有布局与输入适配 | 不重复创建媒体缓存或劫持媒体 src |
| `src/ui/interface.js` | 外观变量、控件、触控尺寸、动效和无障碍 | 仅样式；不注册观察器、计时器或输入监听 |
| `src/patches/` | 站点兼容及既有功能模块 | 名称虽为 patches，但部分为正式功能；以构建清单确定是否启用 |
| `src/mobile/` | 手机大图、缩放与居中 | 只添加手机差异，共用核心采集和播放逻辑 |
| `config/modules.json` | 用户脚本加载顺序、手机增量、扩展源文件映射 | 修改后统一构建，不能只手改生成文件 |
| `apps/extension/background.js` | 扩展权限请求、跨域读取、按站点注入 | 扩展注入顺序仍由这里维护，不能改变初始化依赖顺序 |
| `tools/` | 构建、同步、校验、回归 | 测试默认离线；真实站点验证显式启用 |
| `version.json` | 正式版本号 | 电脑端与手机端保持一致 |

根目录的四份 `.user.js` 和扩展中的映射文件是生成产物；源码变更后执行 `npm run build`。没有引入运行时远程依赖，用户安装的仍是单文件脚本。

## 运行路径

1. 加载版本、设置和站点适配，再初始化核心，最后应用视觉模块；手机包额外加载移动适配。
2. 采集媒体地址，通过增量游标将新增地址加入渲染队列；删除时回退游标并修正待建卡片索引，换组清空游标；每帧按时间预算创建卡片，仅为新卡片注册观察器。
3. 邻近视口的媒体挂载，远离视口时释放来源、保留布局占位；大图开启时暂停网格预览竞争。
4. 切组先读取并验证目标数据，成功后提交；代次和取消信号阻止旧请求覆盖当前组。
5. 关闭或换组清理观察器、预加载和待执行任务；隐藏标签暂停建卡，重新可见后继续。

## 本地验证与发布

```sh
npm ci
npm test
npm run build
```

测试覆盖渲染与回收、筛选、手势、缩放、分组并发和网站兼容。`test-frame-work.mjs` 的计数用于比较重复工作量，不是设备 FPS 跑分。浏览器帧率仍受媒体尺寸、设备、网络与网站脚本影响。

真实 x.810114 接口测试可设置 `FLOWLENS_LIVE_X810114=1` 后运行 `node tools/test-x810114-navigation.mjs`；本机 Node 不走代理时可另设 `FLOWLENS_LIVE_PYTHON=1` 使用 Python 标准库传输。

GitHub Check FlowLens 工作流安装锁定依赖、运行回归、重建并拒绝未同步的生成文件。Pages 发布使用现有手动工作流，安装页与脚本版本在发布后再次核对。

## 结构现状

核心仍包含较多历史功能，尚未全面拆分成独立 ES 模块。此次先明确视觉层与构建配置边界，保持现有共享状态和脚本执行顺序；继续拆分应按功能迁移并同步回归，避免切组和触控逻辑出现多份状态。
